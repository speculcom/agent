先回答一件事：你要不要自己搭Answer one question first: do you need to build one at all

这是本分区存在的唯一理由。如果现成产品已经够用，正确答案是「不要搭」——那就去 成品 Agent，不用往下看。真要自己搭，第一步是认清你要的抽象层。This is the only reason this section exists. If a finished product already does the job, the right answer is "do not build" — go to Finished Agents and stop reading. If you really are building, the first step is being clear which abstraction layer you want.

  1. 1我要最细的控制权，文件系统我自己管I want the finest control and will manage the filesystem myself
    原语型（primitives-only）Primitives only只给你 agent loop 的原语，不替你决定文件系统 / 规划 / 记忆怎么做 —— OpenAI Agents SDK 是这一类。You get the raw agent-loop primitives and it does not decide for you how the filesystem, planning or memory work — OpenAI Agents SDK is in this group.
  2. 2我要一个成熟 CLI 直接变成 API 对象I want a mature CLI turned into an API object
    包装既有 CLIWrapping an existing CLIClaude Agent SDK 捆绑完整 CLI，默认给全工具无沙箱 —— 你省了造轮子，但权限模型是继承来的。Claude Agent SDK bundles a complete CLI with all tools and no sandbox — you save reinventing it, but the permission model is inherited.
  3. 3我要开箱即跑的通用长任务助手I want a general long-task assistant that works out of the box
    batteries-includedBatteries includedDeep Agents 官方自述 opinionated：预置更多东西，也替你做了更多决定。Deep Agents describes itself as opinionated: more is preset, and more has been decided for you.
  4. 4流程要图、要能中断恢复、要多 Agent 协作I need a graph, interruptible resumption, and multi-agent collaboration
    编排框架：LangGraph / Google ADK / CrewAIOrchestration frameworks: LangGraph / Google ADK / CrewAILangGraph 的落盘粒度最明确（每 superstep 存一次图状态），ADK 的图执行引擎最完整，CrewAI 用「角色分工 + 事件流程」两套抽象。LangGraph has the clearest checkpoint granularity (graph state saved every superstep), ADK has the most complete graph execution engine, CrewAI uses two abstractions: role division and event flow.
  5. 5我要它常驻、跨平台、能定时跑I want it resident, cross-platform, able to run on a schedule
    平台型 / 常驻型：OpenHands / Hermes AgentPlatform / resident type: OpenHands / Hermes AgentOpenHands 是带 Web UI 的自托管控制中心；Hermes 更进一步——能挂 Telegram/Discord/Slack/WhatsApp/Signal/Email 六平台，还能 cron 无人值守。OpenHands is a self-hosted control centre with a web UI; Hermes goes further — it attaches to Telegram, Discord, Slack, WhatsApp, Signal and Email, and can run unattended on cron.
  6. 6我只想要个工具用，不想维护I just want a tool to use, not something to maintain
    不该来这个分区You should not be in this section这属于「不自建」那一侧，见 成品 Agent。That belongs on the "do not build" side — see Finished Agents.

⚠ 三个最容易踩的坑：「状态」和「上下文」不是一回事——压缩上下文会丢信息，状态持久化才是长期可靠运行的前提（各家在这两层的完备程度差别很大）；「provider 无关」不等于「本地模型可用」（Claude Agent SDK 只支持 Claude，CrewAI 则点名支持 Ollama）；编排框架不给沙箱——权限边界要自己确认。⚠ Three traps people fall into most easily: "state" and "context" are not the same thing — compressing context loses information, while state persistence is what makes long-term reliable operation possible (and vendors differ a lot in how complete these two layers are). "provider-agnostic" does not mean "local models work" — Claude Agent SDK supports only Claude, while CrewAI explicitly names Ollama support. Orchestration frameworks provide no sandbox — you have to establish the permission boundary yourself.

按抽象层分组By abstraction layer

同一层里也能差很远 —— 两个「编程底座」一个是纯原语、一个是全托管包装 CLI，所以先按抽象层分，再看具体对象。Even within a layer the gap is wide — of two "coding bases", one is pure primitives and one is a fully managed CLI wrapper. So group by abstraction first, then look at the object.

为什么这里不给总分排名Why there is no overall ranking

这不是省略，是方法上的明确取舍。This is not an omission but a deliberate methodological choice.

  • 缺统一实测，就不给分。跨工具的跑分口径不同——题目、预算、执行环境都不一样，A 的 90 分和 B 的 88 分不可比。No shared measurement, no score. Benchmarks across tools use different rules — different questions, budgets and environments. A 90 and a B 88 are not comparable.
  • 「未知」是合法答案。"Unknown" is a legitimate answer.查不到就写「未知」并说明为什么，不用推测填充。缺信息本身也是信息。
  • 来源链接、类型与核验日都在详情页里，可以逐条回去复核。The source link, its kind and the checked date are all on the detail page, so you can walk any of them back and re-check.
  • lifecycle 单独标注。核验日新不等于数据有效——上游归档后数据会失效，所以单独标 active / maintenance / archived。lifecycle is marked separately. A recent check date does not mean the data is still valid — it goes stale when upstream archives the repo, so active / maintenance / archived are tracked separately.
  • 不同层不混排。成品 agent、自己搭的底座、给 agent 装的工具是三种角色，坐标系不同；硬合成一张 33 行的表只会制造假的可比性。Layers are not mixed. Finished agents, bases you assemble yourself, and tools you install for an agent are three different roles with different coordinate systems; forcing them into one 33-row table would manufacture false comparability.
