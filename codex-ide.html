Codex IDE 扩展Codex (IDE extension)

OpenAI
编程 IDE 本地 partial lifecycle: active 核验Checked 2026-10-08

不是独立 IDE，是装进 VS Code / Cursor / Windsurf 的扩展——通过 app server 与 CLI 共享同一套会话机制。Not a standalone IDE but an extension for VS Code / Cursor / Windsurf — sharing the same session mechanism with the CLI through the app server.

适合与不适合When to use it, when not to

已在用 VS Code / Cursor / Windsurf 等编辑器， 希望在同一环境里用 Codex 而不切换工具的人。 需要 IDE 与 CLI 共享会话的人（app server 架构）。

不适合需要独立编辑器的人—— 本形态必须依附已有编辑器，无法单独使用。 另需注意：本地任务依赖编辑器进程常驻， 要「关机后继续跑」须改用云委派（Codex Cloud）。

People already in VS Code / Cursor / Windsurf who want Codex in the same environment without switching tools. People who need IDE and CLI to share sessions (the app server architecture).

Not a fit for people who need a standalone editor — this form must attach to an existing editor and cannot be used alone. Also not a fit where permission behaviour must be strictly identical between IDE and CLI; this round did not verify consistency.

模型与开放条件Model & openness
与 CLI 形态同一套 agent 与配置（官方 IDE 页原文： "It uses the same agent as the Codex CLI and shares the same configuration"）。官方定价页列出可用模型：GPT-5.5、GPT-5.4、 GPT-5.4 mini，Pro 另有 GPT-5.3-Codex-Spark（research preview）。 聊天输入框下有 模型切换器，并可调 reasoning effort （low / medium / high）。默认模型在共享 config.toml 里设 （model = "..."），IDE 与 CLI 共用，故自定义 provider 走同一套 model_providers 配置（见 CLI / SDK 档案）。 BYOK 可用：官方支持用 API key 登录；JetBrains 集成还可走 JetBrains AI 订阅；API key 路径下模型可用范围跟随该 key 的 API 模型。
运行位置Where it runs
IDE 形态是扩展，不是独立编辑器。 官方 README 原文： "If you want Codex in your code editor (VS Code, Cursor, Windsurf), install in your IDE." 即装进 VS Code / Cursor / Windsurf 这类已有编辑器。 这与 Zed（独立编辑器）、Cline Desktop（原生应用）是不同形态。
本地文件Local files
通过宿主编辑器访问工作区文件；上下文来自打开的文件、选区与 @file 引用，另有 Auto Context（自动带入最近文件与 IDE 上下文， 见 /auto-context）。官方口径：工作区 = 当前目录加临时目录 （如 /tmp），写入默认限工作区。Windows 上可原生运行（走 Windows 沙箱）或改用 WSL2（设置项 chatgpt.runCodexInWindowsSubsystemForLinux）。 官方 IDE 文档未描述独立语义索引——本地文件检索由同一 agent 的工具完成（已查官方 features 与 settings 两页）。
关机后的任务Tasks after shutdown
有云端形态，官方称可从 IDE 委派任务到 Codex Cloud。 IDE 页原文："delegate tasks to Codex Cloud"；功能页原文 "Offload longer jobs to a cloud environment"，可用 /cloud 与 /local 切换。云任务在 OpenAI 托管的容器里后台运行 （含并行），因此本地编辑器关闭后云任务仍继续； 本地任务依赖宿主编辑器进程，关闭即停止。 云任务与本地消息共享套餐用量（官方定价页称共用 5 小时窗口）。
工具与扩展Tools & extensions
内置第一方工具与命令已核验：网页搜索（官方称默认启用， 走 OpenAI 维护的搜索缓存，可配 web_search = "live" | "disabled"）、 图像生成（$imagegen，模型 gpt-image-2，计入用量且更快耗尽额度）、 代码审查（/review）、编辑器上下文（@file、选区、拖拽图片）， 以及命令面板命令（chatgpt.newChat / addToThread / addFileToThread / implementTodo）与 TODO CodeLens。 MCP 官方明确支持 IDE 扩展：原文 "Codex supports MCP servers in both the CLI and the IDE extension"， 支持 STDIO 与 Streamable HTTP，CLI 与 IDE 共享 config.toml 里的 [mcp_servers.<name>]（含 enabled_tools 与逐 server、逐 tool 的 approval_mode）。
上下文与记忆Context & memory
app server 架构仍是关键设计——线程可启动、续接与恢复， IDE 与 CLI 共享同一套会话机制与同一份配置。 官方另补三点：从本地会话发起云任务会记住会话上下文 （云任务转回本地续聊也保留上下文）；/status 显示 thread ID、 上下文用量与速率限额；/goal 可设持久目标。 上下文窗口的具体数值与自动压缩策略，官方未在 IDE 文档单列 （压缩在 CLI / SDK 侧经 compact_prompt 等配置项， 已查官方 features 与 slash-commands 两页）。
权限与限制Permissions & limits
IDE 与 CLI 共用同一套沙箱与审批——官方 settings 页明说 "The Codex IDE extension uses the Codex CLI"，审批与沙箱在共享 ~/.codex/config.toml 里配置。 UI 侧有三档审批模式： Chat / Agent / Agent (Full Access)；默认 Agent： 在工作目录内自动读写并执行命令，工作目录外或联网仍需审批； 只有 Full Access 才免审批联网。官方安全页口径（含 IDE extension）：默认 无网络 + 写入限当前工作区， .git / .agents / .codex 递归只读；审批与沙箱键同 CLI （approval_policy / sandbox_mode / [sandbox_workspace_write] network_access 与 network_proxy 域名清单）；Windows 原生沙箱默认 elevated。

头号误解Top misconception

  • 以为 IDE 扩展与 CLI 是两套独立系统，app server 架构让它们共享会话Assuming the IDE extension and the CLI are separate systems — the app server architecture lets them share sessions
