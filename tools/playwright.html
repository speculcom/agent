A browser automation server maintained by Microsoft, driven by the accessibility tree rather than screenshots — no vision model needed, and the output is a structured snapshot.A browser automation server maintained by Microsoft, driven by the accessibility tree rather than screenshots — no vision model needed, and the output is a structured snapshot.

适合与不适合When to use it, when not to

需要浏览器自动化且要保持会话状态的场景： 探索性自动化、自愈测试、长时自主工作流。

不适合高吞吐编码 agent**——README 自己建议这类场景改用 Playwright CLI + SKILLS，因为 MCP 形态要加载大工具 schema 和无障碍树， token 效率更低。 也不适合需要真正网络隔离的场景：官方明确声明来源限制不构成安全边界。

Scenarios where an agent must operate a real browser and read the page as structure rather than as a picture.

Not a fit for visual-only understanding — it drives the accessibility tree, so anything conveyed purely by pixels is out of reach.

模型与开放条件Model & openness
本身不调用模型，是被客户端调用的接口实现。 用 Playwright 的无障碍树（accessibility tree）而非像素输入， 因此不需要视觉模型，输出为结构化快照。
运行位置Where it runs
本地 Node.js 进程（需 Node.js 18+），通过 stdio 通信。 也提供 HTTP endpoint 模式与浏览器扩展模式（Edge / Chrome）。 默认有头模式，可用 --headless 切换。
本地文件Local files
无本地文件访问能力。核心能力是浏览器控制。 用户 profile 默认落盘在 Playwright 缓存目录（按 workspace hash 隔离）， 用 --isolated 可改为仅存内存。
关机后的任务Tasks after shutdown
浏览器进程可保持常驻。--idle-timeout 控制空闲关闭： headless 默认 1 小时关闭，headed 模式默认永不关闭； 下次工具调用会重新拉起浏览器。
工具与扩展Tools & extensions
提供完整的浏览器自动化工具集（导航、点击、输入、快照、截图等）。 输出以无障碍树结构为主，是结构化数据，可直接消费。 具体工具清单需读仓库文档，本站未逐条核验。
上下文与记忆Context & memory
保持浏览器上下文是本 server 的核心价值—— README 明确指出 MCP 形态适合需要持久状态、 丰富内省与迭代推理的 agentic loop， 例如探索性自动化、自愈测试、长时自主工作流。
权限与限制Permissions & limits
需要给浏览器授予权限，且官方明确说明限制手段不是安全边界。 --grant-permissions 可授予 geolocation、clipboard-read、clipboard-write 等权限。 --allowed-origins 与 --blocked-origins 的文档原文明确写着 「does not serve as a security boundary」且不影响重定向。 默认允许所有来源。
适合什么任务Best for
需要浏览器自动化且要保持会话状态的场景： 探索性自动化、自愈测试、长时自主工作流。 不适合高吞吐编码 agent——README 自己建议这类场景改用 Playwright CLI + SKILLS，因为 token 效率更高。
传输方式Transport
支持 stdio，另提供 HTTP endpoint 模式（--endpoint） 与浏览器扩展连接模式（--extension，需装 Playwright 扩展，仅 Edge / Chrome）。 --shared-browser-context 可让多个 HTTP 客户端共用同一浏览器上下文。
认证机制Authentication
stdio 形态无独立认证层，继承客户端用户权限。 HTTP endpoint 模式的认证机制仓库未说明，本次未核验。
权限范围Permission scope
控制的是浏览器而非文件，但风险面同样宽： 默认允许访问所有来源（--allowed-origins 默认放行全部）， 且可被授予地理位置、剪贴板读写等浏览器权限。 官方明确声明来源限制不是安全边界， 需要真正隔离时应使用 --isolated 或容器化网络策略。

头号误解Top misconception

  • 以为 allowed-origins 能当访问白名单，官方明说不构成安全边界且不防重定向Assuming allowed-origins works as an access allowlist — the official docs state it is not a security boundary and does not guard redirects
  • 以为无头模式会常驻，实际 headless 默认 1 小时空闲即关，headed 默认永不关Assuming headless mode stays resident — headless closes after an hour idle by default; headed never closes
  • 在高吞吐编码场景硬上 MCP，官方自己建议改用 CLI + SKILLSDriving MCP in a high-throughput coding workload — the official guidance is to use the CLI + SKILLS instead
