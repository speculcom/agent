先回答一件事：你到底缺什么能力Answer one question first: what capability are you actually missing

MCP 不是「让 AI 更聪明」，是给 AI 接上它本来够不到的东西。如果你要的只是聊天和写代码，你不需要它。你装，它调——9 个条目全是官方 reference server，不含第三方。MCP is not "making AI smarter" — it is giving AI access to what it could not otherwise reach. If all you want is chat and writing code, you do not need it. You install it, the AI calls it — all 9 entries are official reference servers, none are third-party.

    filesystem、gitfilesystem, git两个都是读写权限，git 那一类值得先看 scope 里能限制到哪些目录。Both have read and write permissions; for the git category it is worth checking what directories the scope can be limited to.
  2. 2我要它记住东西、跨会话召回I need it to remember things across sessions
    memorymemory这是最容易被误解的一类——它不是「模型记忆」，是外部知识图谱存储。This is the most misunderstood category — it is not "model memory" but an external knowledge-graph store.
  3. 3我要让 AI 上网拿资料I need AI to reach the web for material
    context7、fetchcontext7, fetch风险最高的一类是 fetch：档案里引了官方警告——可访问本地与内网 IP，无地址白名单、无审批机制。fetch carries the highest risk: the entry quotes an official warning — it can reach local and internal IPs, with no address allowlist and no approval mechanism.
  4. 4我要控制真实浏览器I need to drive a real browser
    playwrightplaywright注意官方明确声明来源限制不是安全边界，需要真隔离得用 --isolated 或容器化网络策略。Note the official explicit statement that source restrictions are not a security boundary; real isolation requires `--isolated` or a containerised network policy.
  5. 5我要点时间 / 拆解推理 / 跨平台搜文件I want time / decomposition / cross-platform file search
    time、sequential-thinking、everythingtime, sequential-thinking, everything三个都是只读，风险最低。All three are read-only, so risk is lowest.

⚠ 一个容易忽略的维度：数据出境。Context7 是本分区唯一以远程服务为默认形态的条目，查询内容会发到 Upstash 服务器；其余八个都是本地 stdio 进程。另外——装 MCP 需要你手动做，调用不需要：server 启动后自动把工具清单报给你的客户端，之后调不调、什么时候调，由 agent 自己判断，你只在审批环节介入。⚠ An easily overlooked dimension: data leaving the country. Context7 is the only entry in this section whose default form is a remote service — queries are sent to Upstash's servers, while the other eight are local stdio processes. And — installing an MCP server is manual; calling it is not: once running, the server reports its tool list to your client automatically, and after that the agent decides whether and when to call it. You only get involved at the approval step.

为什么这里不给总分排名Why there is no overall ranking

这不是省略，是方法上的明确取舍。This is not an omission but a deliberate methodological choice.

  • 缺统一实测，就不给分。跨工具的跑分口径不同——题目、预算、执行环境都不一样，A 的 90 分和 B 的 88 分不可比。No shared measurement, no score. Benchmarks across tools use different rules — different questions, budgets and environments. A 90 and a B 88 are not comparable.
  • 「未知」是合法答案。"Unknown" is a legitimate answer.查不到就写「未知」并说明为什么，不用推测填充。缺信息本身也是信息。
  • 来源链接、类型与核验日都在详情页里，可以逐条回去复核。The source link, its kind and the checked date are all on the detail page, so you can walk any of them back and re-check.
  • lifecycle 单独标注。核验日新不等于数据有效——上游归档后数据会失效，所以单独标 active / maintenance / archived。lifecycle is marked separately. A recent check date does not mean the data is still valid — it goes stale when upstream archives the repo, so active / maintenance / archived are tracked separately.
  • 不同层不混排。成品 agent、自己搭的底座、给 agent 装的工具是三种角色，坐标系不同；硬合成一张 33 行的表只会制造假的可比性。Layers are not mixed. Finished agents, bases you assemble yourself, and tools you install for an agent are three different roles with different coordinate systems; forcing them into one 33-row table would manufacture false comparability.
