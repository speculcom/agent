Google 官方的开源终端 agent，npx 免安装启动。 明确支持 MCP，另有非交互脚本模式。

Google's official open-source terminal agent — npx, no install required. Explicit MCP support, plus a non-interactive script mode.

适合与不适合When to use it, when not to

它适合这些场景：

  • 需要 npx 免安装快速试用
  • 需要 MCP 扩展
  • 需要脚本化非交互运行（CI）
  • 想把 Gemini 多模态生成（Imagen / Veo / Lyria）接进工作流

也适合这些人：

  • 需要大上下文窗口的人 —— 1M token，本分区里明确写出上限的少数
  • 需要「改动可回退」保证的人 —— shadow Git 检查点加 /restore
  • 需要项目级长期指令文件的人 —— GEMINI.md

不适合把额度当成无限用的场景： 免费层有明确日额度（6,000 代码请求 + 240 对话）。 而且 CLI 与代理模式额度合并计算。

Three scenarios fit:

  • You want a quick trial without installing anything (npx leaves no install footprint)
  • You need MCP extensions, especially wiring Gemini's multimodal generation (Imagen / Veo / Lyria) into an agent workflow
  • You need scripted non-interactive runs, for example in CI

Three kinds of people also fit:

  • Anyone who needs a large context window — 1M tokens, one of the few in this track that states a limit
  • Anyone who needs a revert guarantee — shadow Git checkpoints plus /restore
  • Anyone who needs a project-level long-term instruction file — GEMINI.md

Not a fit for treating quota as unlimited. The free tier has clear daily limits: 6,000 code requests + 240 chats/day. And CLI and agent-mode quota are counted together.

模型与开放条件Model & openness

用 Google 自家的 Gemini 系列，模型可以换。 上下文上限明确标了 1M token。

README 首屏原文：「Powerful Gemini 3 models: Access to improved reasoning and 1M token context window」

换模型：命令行用 gemini -m gemini-2.5-flash 指定。 用 Gemini API Key 登录时，官方描述是：

"Model selection: Choose specific Gemini models"

三种接入方式（README「Authentication Options」）：

  • Google 账号 OAuth 登录 —— 免费层用这个，60 请求/分、1,000 请求/日，不用管 key
  • Gemini API Key —— 在 AI Studio 取 key，按量计费
  • Vertex AI —— 企业用，需要项目和区域

模型路由：Plan Mode 可用 general.plan.modelRouting。 它在 Pro（规划）与 Flash（实现）之间自动切换。 另有实验性的 Local Model Routing（Gemma）。

CLI 侧可切换模型的具体清单与版本映射：官方未给出完整列表。 （已查仓库文档与 reference/configuration 两页。）

运行位置Where it runs

本地进程，在终端里跑，靠 npx 免安装启动。

官方把「免安装」写成仓库首屏的卖点，这是它降低上手门槛的地方。

README 原文：「Using npx (no installation required)」

本地文件Local files

内置文件工具默认以工作区为根，边界明确。

官方「File system tools」页原文：All file system tools operate within a rootDirectory (the current working directory or workspace root) for security

工具集：

  • list_directory
  • read_file —— 支持文本 / 图片 / 音频 / PDF
  • write_file
  • replace
  • glob
  • grep_search

哪些要你点头才能动：

  • write_file 与 replace —— 官方标注 "Requires manual user approval"

扩目录：启动加参数 gemini --include-directories ../lib,../docs。 会话内用 /directory add <path>（受限沙箱配置下禁用）。

忽略边界：遵守 .gitignore，也支持同语法的 .geminiignore。

改动可回退：批准改文件的工具时，CLI 会提交一次快照。 它落在 shadow Git 仓库里，不干扰你自己的项目仓库。 可用 /restore 回退。

checkpointing 页记的仓库位置：~/.gemini/history/<project_hash>

原文：「It does not interfere with your own project's Git repository」

语义索引（Code Customization / RAG）的算法与大仓库耗时官方未说明。 （已查 file-system 与 configuration 两页，只有 general.logRagSnippets 这类调试开关。）

关机后的任务Tasks after shutdown

本地 CLI，不支持关机续跑。

非交互 / headless 是脚本化，不是后台。 它仍跑在你自己的机器上。

官方「Headless mode」页原文："Headless mode provides a programmatic interface to Gemini CLI... without an interactive terminal UI"

触发方式是：

  • 非 TTY 环境
  • -p/--prompt

输出可选 JSON 或 stream-json，供 CI 与自动化调用。

执行环境归你：官方未提供厂商托管的常驻执行环境。 仓库里的 GitHub Action 也跑在你仓库的 CI runner 上。

中断可恢复：checkpointing 与 /chat save / /resume 可以保存和恢复会话。 开关是 general.checkpointing.enabled。 general.sessionRetention 默认保留 30 天。 超期自动清理。

额度就是官方用量口径里的每日请求上限。 官方未另设云端额度。

工具与扩展Tools & extensions

明确支持 MCP，而且是它标注的核心特性。

README 原文：「🔌 Extensible: MCP (Model Context Protocol) support for custom capabilities」

MCP 另有独立文档页：/docs/tools/mcp-server。 它举的例子是把 MCP 用来接多模态生成：

「Use MCP servers to connect new capabilities, including media generation with Imagen, Veo or Lyria」

这条例子值得单独记：MCP 在这里不只是接工具， 还能接 Google 的多模态生成能力（图像 / 视频 / 音频）。 这个用法在其它 CLI 工具的仓库首屏里没被强调。

内置工具清单：

  • Google Search grounding（搜索接地）
  • shell

另有非交互模式做脚本自动化。官方有独立章节 「Non-interactive mode for scripts」。

上下文与记忆Context & memory

1M token 上下文 + GEMINI.md 分层上下文 + 自动历史压缩，三项都有官方专页。

上下文窗口：README 首屏写 Gemini 3 models with 1M token context window。

上下文层级（官方「GEMINI.md」页）：

  • ① 全局 ~/.gemini/GEMINI.md
  • ② 工作区目录及其父目录的 GEMINI.md
  • ③ JIT —— 工具访问某目录时，扫描它和祖先目录的 GEMINI.md（至 trusted root）

文件名可由 context.fileName 改（如 AGENTS.md / CONTEXT.md）。

GEMINI.md 页：支持用 @file.md 语法导入。 /memory show 与 /memory reload 可查看与重载。

压缩策略已核到（官方 core 页）：

"When a conversation approaches the token limit... the core automatically compresses the conversation history"

阈值由 model.compressionThreshold 控制。 默认值是 0.5。 也可以 /compress 手动把整个上下文替换为摘要。

跨会话记忆：官方 Memory 工具把持久事实写进 GEMINI.md（项目 / 全局两级）， 随分层上下文注入后续会话。token caching 仅 API key / Vertex 用户可用。

权限与限制Permissions & limits

沙箱、审批、信任目录三层官方都有专页，是本分区里权限面写得最细的一条。

沙箱：官方「Sandboxing」页给了这些方式。

  • macOS Seatbelt —— 默认档 permissive-open：默认拒绝、写限项目目录，但允许读与网络
  • Docker / Podman
  • Windows 原生
  • gVisor / runsc
  • LXC / LXD（实验）

启用方式：

  • -s/--sandbox
  • GEMINI_SANDBOX
  • tools.sandbox

工具级另有 security.toolSandboxing。

沙箱扩张：命令因权限受限失败时，会弹 "Sandbox Expansion Request"。逐次批准可临时放宽。 越界目录可用 SANDBOX_MOUNTS 挂载。

审批模式（configuration 页）：general.defaultApprovalMode 有三个值：

  • default —— 逐次询问
  • auto_edit
  • plan —— 只读

--yolo（全部自动批准）只能在命令行开。

策略引擎（「Policy engine」页）：~/.gemini/policies/*.toml 用规则定义 allow / deny / ask_user。 匹配条件可按工具名、参数、审批模式与交互 / 非交互环境。 规则分 Default / Extension / User / Admin 四级。 Admin 可强制覆盖。

Trusted Folders：默认关闭。 开关是 security.folderTrust.enabled。 未信任时进 safe mode —— 忽略工作区 .gemini/settings.json 与 .env、 禁用工具自动接受、不连 MCP、不加载自定义命令。 CI 想绕过的话，有两条路：

  • --skip-trust
  • GEMINI_CLI_TRUST_WORKSPACE=true

configuration 页另有环境变量脱敏一节。

值得单独记的两处

① 检查点用 shadow Git，不污染你的仓库

批准一个改文件的工具（write_file / replace）时，CLI 会提交一次快照。

  • 快照仓库在 ~/.gemini/history/<project_hash>
  • 它是独立的 Git 仓库，不会动你的项目仓库
  • 要回退就 /restore

出处是 checkpointing 那份文档：

原文：「It does not interfere with your own project's Git repository」

这是本分区里把「安全网」做进机制的少数 —— 多数工具靠「自动提交到你的仓库」，或者「让你自己 undo」。

② GEMINI.md 是项目级长期指令

它相当于把「这个项目怎么做事」写进一个文件， 多形态（CLI / VS Code / JetBrains）都会读它。 这与 Cline 的 .clinerules、Claude Code 的 CLAUDE.md 是同一类机制，值得横向对照。
