GooseGoose

Agentic AI Foundation
编程 终端 本地 开源 多模型 partial lifecycle: active 核验Checked 2026-10-08

本地优先的开源通用 agent：桌面应用 + CLI + 可嵌入 API 三种形态都能跑。

由 Block 创建，现属 Agentic AI Foundation（Linux Foundation）。

provider 可换成 Ollama 等本地模型。

扩展面以 MCP extensions 为核心。

A local-first, open-source general-purpose agent: it runs as a desktop app, a full CLI and an embeddable API.

Created by Block and now hosted by the Agentic AI Foundation (Linux Foundation).

You can point it at Ollama or other local models, and its extension surface is built on MCP extensions.

适合与不适合When to use it, when not to

适合四类人。

  • 想要一个本地优先、可换任意 provider（含本地模型）的通用 agent，而不止写代码的人
  • 需要桌面应用 + CLI 双形态的人
  • 需要以 MCP 扩展能力为中心、可白名单管控的企业
  • 需要把 agent 接进脚本或 CI 的人（goose run --output-format json）

不适合需要「关机后任务继续跑」的场景。

goose 是本地进程。

goose run 的非交互模式只是脚本化执行，电脑一关就中断。

A fit for four kinds of people.

  • People who want a local-first, general-purpose agent that can switch to any provider — including local models — and does more than write code.
  • People who need both a desktop app and a CLI.
  • Organisations that want MCP extensions as the core extension surface, with an allowlist for control.
  • People wiring an agent into scripts or CI (goose run --output-format json).

Not a fit for anything that has to keep running after your machine is switched off.

goose is a local process.

The non-interactive mode of goose run is only scripted execution — close the computer and it stops.

模型与开放条件Model & openness

能用多家模型，也能接本地模型。

官方 README 列了 15+ 家 provider：

"15+ providers — Anthropic, OpenAI, Google, Ollama, OpenRouter, Azure, Bedrock, and more"

接入方式有三种：

  • 直接用 API Key
  • 用本地模型
  • 经 ACP 接已有的 Claude / ChatGPT / Gemini 订阅

本地与自托管这条路是完整的。

Ollama、Ollama Cloud、LM Studio 都能用。 Docker Model Runner 与 Ramalama 也能用。 Ramalama 走 Ollama provider。

任何 OpenAI 兼容端点也能接。 OPENAI_HOST 可指向自建的 vLLM / KServe。

订阅接入分两类：

  • CLI Provider：cursor-agent
  • ACP Provider：claude-acp / codex-acp 后者把 goose 的 extensions 作为 MCP 传给对方

选模型有两个入口。 一个是 Desktop 的 Models 标签，一个是 goose configure。

官方提示一件事：goose configure 不支持输入自定义模型名。 这种情况要改 GOOSE_MODEL，或者走 Desktop。

官方另称，tool calling 目前以 Claude 4 表现最好。 官方还推荐参考 BFCL 榜单。

运行位置Where it runs

本地优先，三种形态都有。

  • 桌面应用：macOS / Linux / Windows
  • 完整 CLI：面向终端工作流
  • 可嵌入的 API：GDK / SDK

官方 README 原文：

"A native desktop app for macOS, Linux, and Windows. A full CLI for terminal workflows. An API to embed it anywhere. Built in Rust for performance and portability."

代码在本机跑。

模型请求要么出网，要么打到本地模型端点。

另有 goose serve。 Desktop 默认在后台起它，它是个本地 ACP server。

也可以把 goose serve 单独跑在远程 VM 上，再让 Desktop 连过去。

本地文件Local files

靠内置的 Developer 扩展读写文件、执行命令，默认权限很宽。

Developer 扩展页列出的工具：

  • shell —— 执行命令，官方标注 High 风险
  • write —— 创建 / 覆盖文件，High
  • edit —— 精确替换文本，High
  • tree —— 列目录树，Low
  • read_image —— 看图，Low

官方原文说得很直白：

"goose can run system commands with your user privileges and edit any accessible file without your approval"

另外两点：

  • MCP Roots 会把当前工作目录共享给支持 roots 的扩展
  • 可以在 Docker 容器里跑扩展（--container 与 goose-in-docker 教程）

还有独立的 Analyze 扩展，做语义分析与调用图。

关机后的任务Tasks after shutdown

本地进程，不支持关机续跑。

CLI 会话随终端结束。

模型请求在本机发起。

非交互不是后台：goose run 只是脚本化执行。 它一次跑完就退出，仍占用本机进程（详见 tools 轴）。

有定时与远程入口，但都依赖本机在线：

  • Recipes 的定时调度（schedules）
  • goose serve ACP server
  • 把 Desktop 指向远程 goose server
  • Roaming Agents（从另一台机器连到正在运行的 goose）

主机一关机，任务即中断。

工具与扩展Tools & extensions

MCP 是一等公民：extensions 就是 MCP server。

官方 README 原文：

"Connect to 70+ extensions via the Model Context Protocol (MCP) open standard"

传输方式已核到两种：

  • stdio：--with-extension，可带 ENV=val 与显式名字
  • Streamable HTTP：--with-streamable-http-extension <url>

另有 --with-builtin。

内置扩展（官方 Browse Extensions 页）：

  • Developer
  • Computer Controller
  • Memory
  • Auto Visualiser（MCP-UI）
  • Code Mode（用 JS 调 MCP 工具）
  • Summon（加载技能并派发子代理）
  • Top of Mind
  • Analyze 等

扩展白名单（Extension Allowlist）可限制企业内可装的 MCP server。 并支持 MCP Elicitation、MCP Roots 与 MCP Apps。

非交互命令 goose run 的参数：

  • -t "text" / -i file / -i -（stdin）
  • --output-format json|stream-json
  • --no-session
  • -s 转交互
上下文与记忆Context & memory

会话落本地 SQLite，可续接、可分叉。

官方 CLI Commands 页记了一条变化：

自 1.10.0 起，会话存于 SQLite 数据库 sessions.db，不再是单个 .jsonl

会话操作命令：

  • goose session -r —— 续接
  • --fork —— 复制历史，开新会话
  • --edit —— 用编辑器改对话
  • session list / rename / remove / export —— 可导出 markdown / json / yaml

压缩：官方 changelog 提到过这一条。

压缩发生在 unrolled agent loop 的工具边界。

记忆：内置 Memory 扩展提供持久上下文。 也就是跨会话的信息存储。

Top of Mind 每轮注入持久指令。 官方另有 goosehints 一类的上下文工程手段。

权限与限制Permissions & limits

默认就是最宽松的一档，值得单独记。

官方 Developer 扩展页原文：

"goose runs in Autonomous permission mode by default"

也就是不经审批即可执行 shell 命令、改任意可访问的文件。

四档权限模式（GOOSE_MODE 或会话内 /mode）：

  • auto —— 无需审批
  • approve —— 每次动作都要审
  • smart_approve —— AI 判断哪些要审
  • chat —— 禁用全部工具

工具级权限也可以单独设。

在 approve / smart_approve 下，每个扩展工具有三种策略可选：

  • Always allow
  • Ask before
  • Never allow

数据面：官方 Usage Data 页说明了两件事。

收集匿名用量数据需首次征得同意。 同意与否可随时更改。

诊断包 goose session diagnostics 会包含会话消息与配置。 官方提示分享前先检查。

模型推理的数据流向取决于你选的 provider。 goose 本体是 Apache-2.0 的本地程序。

头号误解Top misconception

  • 以为默认有人工审批——默认 Autonomous 模式，不确认即可执行命令、改文件Assuming approval is on by default — it runs in Autonomous mode and will execute commands and edit files without asking.
  • 以为它只写代码——官方定位是通用 agent（研究、写作、自动化、数据分析）Assuming it only writes code — the official positioning is a general-purpose agent (research, writing, automation, data analysis).
  • 以为装上就能用——首次使用必须先配置 LLM provider（goose configure）Assuming it works right after install — you must configure an LLM provider first (goose configure).
