JunieJunie

JetBrains
编程 IDE 多模型 本地 partial lifecycle: active 核验Checked 2026-10-08

Junie 是 JetBrains 官方的 AI coding agent。 它的形态是插件加 CLI：插件装进 JetBrains IDE，CLI 跑在终端与 CI/CD 里。

三个招牌：先出计划再写代码、用真调试器排障、不锁模型。 Plan mode 产出结构化计划文档，确认后才实现。 排障时它接管调试会话、下断点，而不是加 println。 模型上支持 BYOK，也能接本地模型。

Junie is JetBrains' coding agent, installed as a plugin — the official install page states "The Junie plugin is not bundled and not enabled in JetBrains IDEs by default" — and extended in March 2026 by a standalone Junie CLI for the terminal, any IDE, CI/CD and GitHub / GitLab. Its official framing is LLM-agnostic: "Junie supports all the top-performing models from OpenAI, Anthropic, Google, and Grok." On the IDE side it plans before it codes and, since GA, drives your IDE's real debugger rather than adding println.

运行位置Where it runs

它是插件，不是独立编辑器；另有独立的 Junie CLI。

官方 Install 页的原话：

官方原文："The Junie plugin is not bundled and not enabled in JetBrains IDEs by default"

宿主覆盖 JetBrains 全家桶与 Android Studio：

  • CLion、GoLand、IntelliJ IDEA、PhpStorm、PyCharm Pro
  • Rider、RubyMine、RustRover、WebStorm 与 Android Studio

官方还给了各 IDE 的最低版本。 例如 IDEA Ultimate / PyCharm Pro / WebStorm / GoLand 需 2024.3.2+。

第二条腿是 Junie CLI（2026-03 进入 Beta）。 终端、任意 IDE、CI/CD 与 GitHub / GitLab 都能跑。 ReSharper 2026.2 把它带进 Visual Studio（Preview）。 2026-08 起另有本机推理的 Junie Local。

本地文件Local files

它只动你当前项目的文件；出项目要单独批准。

每轮执行后，Junie 会列出本次新增与修改的文件。 每个文件都有 diff 查看链接。 在 Done 面板里，你能逐文件选择性回滚。 然后再决定接受还是拒绝整次执行。 它执行的命令输出，可以在 Junie 的终端里看。

「项目外」是一条显式边界。 Action Allowlist 里有两条独立规则，默认都需要批准：

  • 「Read outside project」
  • 「Write outside project」

想限定它处理哪些文件与目录，用 .aiignore。 它的语法和 gitignore 同款。 官方提醒：它只保护内容，文件名与目录名仍然可见。

IDE 语义索引的实现细节，官方未单列。 （已查 aiignore 与 diffs-and-review 两页。）

工具与扩展Tools & extensions

能力按模式分层，招牌是用真调试器。

四种模式：

  • Code mode —— 拆出多步计划并自主执行：跑命令、建文件、改代码、跑测试
  • Ask mode —— 只读探索与分析
  • Plan mode —— 先产出可编辑的结构化计划，再实现
  • Auto —— 由它自选

调试不是加日志，是真的接管调试会话。 GA 版起，Junie 能启动或接管调试会话。 它在项目码、库码乃至反编译的 .class 文件里下断点。 它还能查看栈帧与线程状态，并求值表达式。

官方原话："uses the debugger, not println"

另有 PR 审查与 git 工作流。 还有 /demo：跑一遍功能，产出视频 / 截图 / HTML 报告。

MCP 官方支持，但目前只有 stdio 传输。 mcp.json 分两级：全局 ~/.junie/mcp.json，项目 .junie/mcp。 它能自动推荐相关的 server。

官方原文："Only MCP servers that use the Standard Input/Output (stdio) transport type are currently supported"

上下文与记忆Context & memory

计划是可提交的工件，Guidelines 是持久上下文。

Plan mode 的计划不是一次性对话。 计划文档存在 .junie/plans，可以提交进版本库。 它按产品需求、技术设计、交付阶段（可选测试策略）分页。 需求含糊时，Junie 会先反问，确认之后才实现。

.junie/guidelines.md 是持久层。 它会被加进每一个任务，可以版本控制、可以复用。 官方另有一个 junie-guidelines 目录。

官方还称 Junie 能 context-aware by default，并说它做得到 next-task prediction。 连上 JetBrains IDE 后，还有语义重构与智能搜索。

上下文窗口与压缩策略，官方未给数字。 （已查 customize-guidelines 与 out-of-beta 博客两处。）

权限与限制Permissions & limits

默认每个动作都要审批。 Brave Mode 能一次放开，但官方不建议。

官方把动作分成 safe 与 sensitive 两类。

官方原文："Most terminal commands, code execution, and execution of MCP tools are considered to be sensitive actions, and Junie by default requires explicit approval from the user"

Brave Mode 可以一次性放开所有敏感动作。

官方原话："using brave mode is not recommended"

Action Allowlist 按类型加白：

  • Terminal（支持正则）、RunTest、Build、Preview
  • MCP、Read outside project、Write outside project
  • Edit build scripts —— 它可能触发代码执行，所以单独设闸

ls / cd / pwd 默认免确认。

.aiignore 保护文件内容。 但官方提示：Brave Mode，或命中白名单的命令，可以绕过。
