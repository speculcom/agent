Cursor CLICursor CLI

Anysphere
编程 终端 多模型 CI 云端 partial lifecycle: active 核验Checked 2026-10-08

Cursor 的终端形态，与编辑器共用同一账户、模型与 mcp.json—— 官方称它支持「print automation for scripts and CI pipelines」，命令名为 agent； 相对 IDE 形态多出 headless 与把会话交给 Cloud Agent / 持久会话两条路径。The terminal form of Cursor, sharing one account, model catalogue and mcp.json with the editor. The official CLI changelog treats it as its own product line (separate from IDE / Agents Window / SDK), and the docs describe headless use as "print mode (-p, --print) for non-interactive scripting and automation". The command is agent (installed under ~/.local/bin), and beyond plain terminal work it adds two paths the IDE form does not have: handing a conversation to a Cloud Agent by prepending & to a message, and persistent sessions (agent persist, detaching with /detach) that, in the official wording, "keep agents running after you disconnect". Permission tokens (Shell / Read / Write / WebFetch / Mcp) are enforced from ~/.cursor/cli-config.json or a project-level .cursor/cli.json, with deny taking precedence over allow.

适合与不适合When to use it, when not to

在终端里做工程任务、写脚本、进 CI/CD 的人——官方给了 GitHub Actions 与 cookbook。 已用 Cursor、希望编辑器与终端共用同一份账户、模型与 MCP 配置的人。 需要把会话交给 Cloud Agent 或持久会话继续跑的人。

模型与开放条件Model & openness
与 Cursor 编辑器同源，模型清单与账户绑定。 官方 CLI 落地页把可选模型示例 列为 Auto、Composer 2、Opus 4.6、Codex 5.3 High Fast、Gemini 3 Pro、Grok， 并写「Anthropic、OpenAI、Gemini、Cursor 等提供的前沿模型」； 模型与价格页另列 Claude 4.6 Opus / Sonnet、Gemini 3.1 Pro、GPT-5.3 Codex、 GPT-5.4、Grok 4.20 与 Composer 2。切换用 --model <model>、--list-models、 agent models、/model。企业可用管理策略限制可用模型：官方 CLI changelog 原文 "Admin Team model restrictions apply in the CLI"，被限制的模型传给 --model 会带限制信息退出。v2026.09.28 修复了「--model 可能静默运行较短基础模型」。 与 ./cursor.md 的差异只在入口，模型目录不因形态而变。
运行位置Where it runs
本地终端进程：官方安装脚本装到 ~/.local/bin（Windows 原生用 PowerShell）， 命令名为 agent；默认自动更新，agent update 手动升级。 生命周期主要绑定终端会话，但官方另给多条「脱离终端」路径（见 background）。 与 ./cursor.md 的 IDE 形态对照：同一账户与配置，差异在交互面是终端、 可脚本化；且 agent acp 能把 CLI 当作 ACP server 跑在 stdio 上供自定义客户端接入。
本地文件Local files
在仓库/工作区内操作，并可用 Git worktree 隔离改动。 --workspace <path 指定工作区，-w/--worktree [name] 在 ~/.cursor/worktrees/reponame/name> 建新 worktree（与编辑器共用保留规则）。写盘默认收紧：官方 headless 页原文 "Without --force, changes are only proposed, not applied"，脚本里要落盘需配 --force（或 --yolo）；注意 parameters 页另有 "Has access to all tools, including write and shell" 的表述，两页口径并存。 规则读取 .cursor/rules 与项目根的 AGENTS.md、CLAUDE.md； 读写范围由 permissions 的 Read(...) / Write(...) 精确控制。
关机后的任务Tasks after shutdown
终端进程随会话结束，但官方提供三条「脱离终端」路径。 一是 Cloud Agent handoff——会话里给消息前加 &，官方称 "continue running while you're away"，可在 web 或移动端 cursor.com/agents 取回； 二是持久会话（v2026.08.26 changelog 原文 "Keep agents running after you disconnect"）：agent persist 启动、/detach 脱离、agent persist attach 重连， agent persist list / stop 管理；三是 agent worker——官方称启动 "a private cloud worker that runs agents in your environment"。 三条路径各自的执行环境归属与额度限制，官方页面未分别写明。
工具与扩展Tools & extensions
内置工具面 + MCP + ACP 三层都已核到。 官方 using 页原文 "Agent has tools for file operations, searching, running shell commands, and web access"；Shell Mode（/shell，/sh、/run 为别名）在登录 shell 跑命令。 MCP：CLI "automatically detect and respect your mcp.json"， 即 .cursor/mcp.json 或 ~/.cursor/mcp.json，与编辑器共用同一批 server； 另有 agent mcp（login / list / list-tools / enable / disable） 与 --approve-mcps。ACP：agent acp 以 stdio + JSON-RPC 对外提供 ACP server。 扩展机制另有 plugins（--plugin-dir、/plugin）、skills（可粘成 custom mode） 与 .cursor/rules。
上下文与记忆Context & memory
会话可恢复、可分叉、有压缩。 继续会话用 --resume [chatId]、--continue、 agent resume、agent ls、/resume；/fork 把当前会话分叉成新会话； /rewind 跳回先前消息；上下文压缩用 /summarize（/compress 为别名）。 v2026.09.22 修复「摘要后丢掉最新一条请求或整段会话」——现在会逐字保留最近一条 用户消息，摘要失败或被中止则保留原会话。长期上下文靠 rules 与 skills： .cursor/rules 与 AGENTS.md / CLAUDE.md 自动加载；/goal 可给长期目标 （官方标 "Rolling out"）。跨会话记忆的存储位置官方未在此页说明。
权限与限制Permissions & limits
权限设计是本形态最细的一块，另有 sudo 凭据保护。 配置文件为全局 ~/.cursor/cli-config.json 与项目级 <project>/.cursor/cli.json，权限 token 分五类： Shell(cmd)、Read(path)、Write(path)、WebFetch(domain)、Mcp(server:tool)， 用 permissions.allow / permissions.deny 控制，deny 优先于 allow。 默认下每条终端命令都要批准——官方 using 页原文 "Before running terminal commands, CLI will ask you to approve (y) or reject (n)"； --force（别名 --yolo）放行。沙箱由 /sandbox 或 --sandbox enabled|disabled 控制，官方写 disable 时「用 allowlist 模式」。需要 sudo 时弹掩码密码框， 官方称密码经安全 IPC 直达 sudo，"The AI model never sees it"。 CI 侧官方推荐「受限自主 + permission-based restrictions」，并把指令写入 permissions.json 配 Auto-review。
